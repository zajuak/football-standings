# 北大足协积分榜生成器

[在线使用](https://zajuak.github.io/football-standings/) · [GitHub 仓库](https://github.com/zajuak/football-standings)

GitHub Pages 提供编辑器，Cloudflare Workers + D1 保存所有赛事及提交历史。支持赛果录入、修改、删除，公平竞赛积分、同分排序、球队与小组管理，以及 SVG / PNG 积分榜海报导出。

## 数据保存

- 打开页面自动读取云端最新数据，无需口令或登录；其他设备的更新在页面空闲时每 15 秒检查，回到页面时也会检查。
- 只有赛事内容发生变化时才提交完整快照。切换赛事、查看历史和刷新页面不新增历史；前端与数据库均进行内容比对。文字输入短暂停顿后自动保存。
- 所有历史保存在 D1，不自动删除或截断。删除赛果、重置、恢复旧版本后，之前的版本仍可查看和导出。升级前已存在的重复历史也会保留。
- 本机仅缓存当前数据与待同步队列。断网后可以继续编辑，联网后补传；在首次成功读取云端前暂停编辑，避免默认数据覆盖已有数据。
- 两个页面同时修改时，过期提交会先存入历史，再提示选择使用哪个版本，不直接覆盖其他人的更新。
- “历史与备份”支持分页恢复、导出完整云端历史、导入 JSON 备份。
- 积分榜预览可切换“小组积分榜”和“组间晋级比较”，选择各组共同拥有的名次，并导出对应 SVG / PNG。人数不等时沿用既有规则：较多球队的小组剔除与本组末位的比赛成绩，公平竞赛积分保留。
- “新增赛事”支持创建小组赛或联赛，随后添加球队与小组。赛事使用独立 ID，不限定现有两项赛事。自定义赛事重置时保留球队结构并清空成绩。

按内部使用需求，当前接口**没有身份验证**，知道网址或接口地址的人可以读写数据。CORS 只限制普通浏览器跨站请求，不是访问控制。原始 Word、实际云端赛果和私人备份不会提交到 GitHub。

## 开发与发布

要求 Node.js >= 22，没有第三方前端运行依赖。

```sh
npm test
npm run build
npm run dev
```

本地静态预览为 `http://127.0.0.1:8081/`，构建产物位于 `pages-dist/`。云端 CORS 默认仅允许正式 GitHub Pages 来源；本地联调可使用 Wrangler 本地数据库和测试中的内存 SQLite，避免修改正式数据。

- `public/app.mjs`：页面、赛事切换、备份和自动刷新
- `public/cloud-sync.mjs`：自动连接、离线队列和冲突处理
- `public/state-content.mjs`：规范化内容比对，排除浏览偏好与格式版本号
- `public/core.mjs`、`public/poster.mjs`：积分规则、赛事结构与海报
- `public/local-history.mjs`：保留的旧版 IndexedDB 工具，当前页面不再写入本机历史
- `cloudflare/`：Worker API、D1 迁移及部署说明
- `tests/`：积分、云端同步、去重、冲突与旧版历史兼容测试

构建时按源码内容给入口、样式及全部模块依赖添加统一资源版本，避免升级后新页面混用浏览器缓存的旧脚本。

推送 `main` 后 GitHub Actions 自动测试并发布前端；后端部署见 [cloudflare/README.md](cloudflare/README.md)。`scripts/copy-editor.mjs` 用于原维护目录的源文件同步；独立克隆时直接修改仓库中的文件即可。

## 手机同步排查

网页位于 GitHub Pages，同步接口位于 `football-standings-api.junkaizhao404.workers.dev`，两者的网络可达性独立。可用网页中的“检查云端接口连通性”链接打开 `/health`：正常返回 `ok: true`。如果打不开，先更换网络确认；前端无法绕过接口域名的网络不可达。对国内直连有要求时，应配置可达的自定义 API 域名或后端并实测，前端地址可继续保持 GitHub Pages。

同步请求使用 `AbortController` 和计时器，兼容没有 `AbortSignal.timeout()` 的旧版手机浏览器；网络失败或超时会显示具体提示，待同步队列会保留。
